Overview

picar_ros is a hobby robotics project built on a Sunfounder PiCar-X. The goal was to progressively build an autonomous AprilTag chasing system, starting from simple pixel-space control and working toward full image-based visual servoing with ROS2 trajectory visualization. Three versions were developed over June 2026, each on its own branch: pixel-space PID control, a world-frame TF system with live RViz2 trajectory recording, and image-based visual servoing (IBVS) with a single-tag world anchor.

The car itself is a Raspberry Pi 4 with a Pi Camera Module 3 on a pan/tilt gimbal, front steering, and rear drive motors. It talks over WebSocket to an Ubuntu machine running ROS2 Humble, which handles TF publishing, trajectory recording, and RViz2 visualization. AprilTag36h11 detection (via pupil-apriltags) drives every version's control loop.

v1 — Camera Lock branch: main

Goal: get the car to autonomously detect AprilTag ID 0 and drive toward it using a PID controller on horizontal pixel error. No world frame, no gimbal movement, camera fixed.

A tag chase mode was integrated into the browser dashboard. The operator clicks a toggle, a 3-second countdown runs, then the car steers toward the tag's horizontal center and drives forward at a fixed speed, stopping once the tag is within a configurable distance threshold. The entire camera pipeline was taken over from scratch: a FastAPI server owns the single Picamera2 instance for the full session, serves an MJPEG stream, and passes frames to the chaser on each tick.

Notable bugs fixed

  • Vilib/Picamera2 incompatibility — Vilib used a Picamera2 internal API removed in a later release; fixed by dropping Vilib and having the server own Picamera2 directly.
  • WebSocket concurrent-send corruption — multiple tasks calling ws.send_json() interleaved and silently dropped clients, leaving the chase toggle stuck active. Fixed with one asyncio.Queue per connection drained by a single serial sender task.
  • Camera color inversion — capture_array() returned RGB regardless of the configured format name; fixed by using RGB888 directly with no color conversion.
  • Tag ID mismatch — physical tag was ID 0, config said ID 1.
  • Broadcast flood killing the sender — 30fps per-frame broadcasts triggered transient WebSocket exceptions that silently killed the sender task; throttled to 10fps and made the sender resilient to individual send errors.

Limitations carried into v2: gimbal locked at 0°, fixed forward speed regardless of distance, no latching stop, no world-frame trajectory recording.

v2 — World TF branch: test/v2_world_tf

Goal: establish a fixed world coordinate frame using a pair of AprilTags mounted to a wall, record the car's trajectory in that frame, and visualize it live in RViz2.

Tags 2 and 3, mounted to the wall roughly 7cm apart, act as a dual-tag world anchor. The system searches for both simultaneously and validates geometric consistency (0.025m tolerance per axis) before locking in the world frame: idle → world_search (15s timeout) → countdown → chasing. The chase target itself remains tag 0. A new tf_bridge ROS2 node on the Ubuntu side subscribes to the Pi's WebSocket feed, computes world → camera TF, and publishes trajectory LINE_STRIP MarkerArrays plus per-cycle PLY point clouds. A picar_description ROS2 package with a URDF (pan/tilt gimbal, body, four wheels) was added so the car renders correctly in RViz2 via robot_state_publisher.

Jitter finding: trajectory plots showed sharp zig-zags even with the car stationary. The root cause is AprilTag PnP pose ambiguity — a planar tag has two valid pose solutions, and the solver alternates between them frame to frame, producing roughly ±15cm of Y-axis noise while stationary.

Notable bugs fixed

  • Manual Track did nothing — a variable was missing from a global declaration.
  • Motors froze mid-drive with steering stuck — a per-connection watchdog timer became orphaned on browser reconnect; promoted to a module-level global and made the watchdog re-center steering on freeze.
  • Double-shutdown traceback on Ctrl-C — rclpy.shutdown() was called twice; wrapped in try/except.

Tag-Size Noise Experiment

Hypothesis: larger printed tags reduce PnP pose ambiguity by giving the corner detector more pixels to work with. Four sessions were recorded on 2026-06-23 with a stationary camera, varying tag size and lighting, and measuring the standard deviation of the estimated position on each axis.

Bar width proportional to σZ (depth noise), the axis most affected by PnP pose flips.

Conclusion: tag size is the dominant factor. The 20cm tag reduces depth noise roughly 3x versus the 5cm tag. For 5cm tags, ambient lighting creates glare that degrades corner localization; for 20cm tags, lighting is a secondary concern.

v3 — IBVS branch: test/v3_ibvs

Goal: add image-based visual servoing (IBVS) so the pan/tilt gimbal actively tracks the tag in pixel space, and drop the wall-mounted tag pair in favor of using tag 0 alone as a world anchor.

Pan/tilt servo control is driven directly by pixel error: eu = tag_x - cx, ev = tag_y - cy, smoothed with an EWMA (α = 0.8). A 10px deadband and 30px lazy band prevent hunting, and each axis is capped at 2°/frame. The first tag 0 detection seeds a world anchor transform; every subsequent frame derives the camera's world pose by chaining through that anchor and the current camera-to-tag transform.

ModeDescription
ibvs_testIBVS pan/tilt only, no drive, no TF — for servo tuning.
manual_ibvsIBVS pan/tilt + manual WASD drive from the dashboard.
rat_chaseIBVS pan/tilt + autonomous car centering + forward drive. Tag 0 only.
world_ibvsFull v2-style behavior: dual-tag world frame + countdown + TF chase.

Notable bugs fixed

  • TF never broadcast in test modes — the TF publish call only ran inside the autonomous-chase branch, so ibvs_test and manual_ibvs never reached it despite detecting tags correctly.
  • A Z-filter that rejected every valid frame — two rounds of a bad threshold check meant valid camera-height readings were rejected outright; made the filter configurable and defaulted it off.
  • A velocity gate that rejected all hand-carried movement — a 10cm/frame gate tuned for autonomous driving discarded nearly every step when the car was carried by hand for testing; added a separate, looser jump threshold for the anchor-mode path.

See the full debrief for the remaining bugs (a stuck-red RViz marker from Volatile QoS, wheels rendering as vertical posts from a URDF rotation error, and joint states not publishing before the Pi connects).

Current status: IBVS pan/tilt tracking and the single-tag world frame are confirmed working. rat_chase autonomous drive is fully implemented but not yet tested on the floor.
